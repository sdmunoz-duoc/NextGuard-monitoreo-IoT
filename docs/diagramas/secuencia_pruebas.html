Secuencia de las pruebas

Cinco escenarios entre el ESP32, la API y PostgreSQL (más el verificador): qué mensajes se cruzan y qué respuesta se espera.

  • A y B muestran por qué (device_id, seq) es la clave de idempotencia: el reintento recibe 200 y no genera otra fila.
  • En C la API responde sin consultar la BD; el ESP32 no descarta la muestra porque un 401 es un problema de configuración, no del dato.
  • En D la BD caída se ve igual que la API caída desde el ESP32 (5xx o timeout); /health distingue ambos casos (503 = BD).
